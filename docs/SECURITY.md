# Security and publication

Review the public commit tree, author metadata and objects before any push. The capture boundary is an explicit allowlist. Exclude Keyring and KWallet stores, browser data, private keys, authentication logs, credentials and secret environment files, private project references, personal email and home paths, machine and volume IDs, boot entries, backups, and unlicensed media. Avoid printing suspected values during review. A scanner supplements manual inspection and cannot prove the absence of secrets.

Review `scripts/public-files.txt` and run `scripts/publication-check --worktree` before staging. Stage only its allowlisted files. Run `scripts/publication-check` and review the full staged diff, upstream licenses and author metadata before committing. Run `scripts/publication-check --objects --base=origin/main` before the initial push to check all Git objects in the fresh clone. Do not commit a finding, even on a temporary branch. If data was committed, stop publication and audit every object that could be sent. If it became public, presume exposure and rotate affected credentials.

The desktop account renders assets without privileges. The SDDM and Limine publishers authenticate local peers, validate bounded inputs and use fixed destinations. Their units are root-owned, and the desktop cannot edit their executable files or write to the ESP. Limine and kernel/snapshot tools coordinate through the same boot lock. Keep the existing boot integrity checks and preserve payload hashes. PAM remains the authentication boundary. The Brave guard fails closed when readiness cannot be established.
